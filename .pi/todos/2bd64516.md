## Problem
As a Vim user, using a mouse while browsing interrupts a keyboard-first workflow. Existing keyboard-driven browser control can feel too slow if it requires heavyweight overlays, delayed hint rendering, or multi-step interactions for common actions.

## Goal
Build a blazing-fast solution that allows full control and interaction with Chrome using only the keyboard, minimizing or eliminating the need for a mouse while preserving Vim-style speed and flow.

## Performance priority
Performance is a first-class requirement, not a nice-to-have. Common actions should feel instantaneous and should avoid visible lag, expensive page scans, blocking UI updates, or unnecessary automation overhead.

## Desired capabilities
- Scroll pages from the keyboard with immediate response
- Click/open links without the mouse using fast, low-latency hints or targeting
- Press buttons and interact with common website controls
- Navigate quickly in a Vim-like workflow
- Support common browser actions such as back/forward, tab switching, focusing the address bar, find-in-page, reload, and opening links in new tabs
- Keep interactions minimal: prefer one or two keystrokes for frequent actions
- Provide a fast, seamless browsing experience for common actions

## Success criteria
- Most common browsing actions can be performed from the keyboard
- Mouse usage is only needed for rare edge cases
- Workflow feels natural for Vim users
- Common commands respond with no perceptible delay
- Link/button hinting appears quickly, remains responsive on large pages, and avoids slowing down page interaction
- The solution favors lightweight implementation choices and benchmarks/regression checks for interaction latency where practical
